field note · 2026-08-27 · macOS Terminal.app

Claude Code ↔ Codex CLI
터미널 간 에이전트 통신

서로 다른 회사의 AI 코딩 에이전트를 한 대의 Mac에서 대화·협업시키는 방법. 공식 API도 플러그인도 없이 — 터미널, 파일, AppleScript만으로.

Claude Code 2.1.247Codex CLI 0.150.1Terminal.app 2.15macOS 26.6.2

§0요약

채널방향지연수단비고
① 세션 메시지Claude ↔ Claude즉시ListAgents · SendMessageClaude Code 내장. Codex엔 없음
② 터미널 타이핑Claude → Codex즉시AppleScript do script … in tabEnter 별도 전송 필요
③ 화면 읽기Codex → Claude폴링AppleScript history of tab보조 채널
④ 게시판 파일전원 ↔ 전원초 단위HANDOFF.md + 파일 감시유일한 공용·영구 채널

파일이 프로토콜이다. 서로 다른 도구는 메시지 API를 공유하지 않지만 같은 디스크를 공유한다. 지시는 ②로 밀어넣고, 응답은 ④로 받는다.

§1배선도

네 탭이 같은 프로젝트 폴더에서 실행. 실선 = 즉시 push, 점선 = 파일·화면을 통한 pull.

§2채널별 레시피

Claude ↔ Claude 세션 메시지

ListAgents                              → 동료 세션 이름 (예: claude-f0)
SendMessage(to="claude-f0", message="…", notify_when_idle=true)

상대가 다음 턴에 <cross-session-message>로 받는다. 회신도 같은 방법. notify_when_idle을 켜면 상대가 멈췄을 때 알림이 온다.

Claude → Codex 터미널에 직접 타이핑

Codex가 떠 있는 tty를 찾는다:

ps -eo pid,tty,command | grep -E "bin/codex$"
#  95839 ttys001 …/bin/codex
#  95896 ttys002 …/bin/codex

Terminal.app 탭을 tty로 골라 텍스트를 넣는다:

on sendTo(ttyName, msg)
  tell application "Terminal"
    repeat with w in windows
      repeat with t in tabs of w
        if (tty of t) is ttyName then
          do script msg in t      -- 입력창에 타이핑됨
          delay 0.5
          do script "" in t       -- ★ Enter. 이게 없으면 제출되지 않는다
          return "sent"
        end if
      end repeat
    end repeat
  end tell
end sendTo
sendTo("/dev/ttys001", "claude-13이다. HANDOFF.md T-2 줄을 …로 바꿔줘.")

Codex 입장에서는 사용자가 타이핑한 것과 구분되지 않는다. macOS가 최초 1회 "Terminal 제어 허용" 권한을 묻는다.

함정 (실측) — do script가 붙이는 줄바꿈을 Codex TUI는 제출로 받지 않는다. 첫 시도에서 메시지는 입력창(›)에만 남아 있었고, 빈 do script ""를 한 번 더 보내자 제출됐다.

Codex → Claude 화면 읽기 (보조)

tell application "Terminal" to repeat with w in windows
  repeat with t in tabs of w
    if (tty of t) is "/dev/ttys001" then
      set h to history of t
      log text ((length of h) - 600) thru (length of h) of h   -- 마지막 600자
    end if
  end repeat
end repeat

Codex가 Working…인지, 무슨 답을 했는지 확인할 수 있다. 정형 응답이 필요하면 ④를 쓴다.

HANDOFF.md 전원 공용 작업 게시판

# HANDOFF — 작업 게시판 · 사이클 N (관리: Claude claude-13)
## 게시판 공통 규칙
1. 자기 담당 작업 외 파일을 건드리지 않는다.  2. 키는 어디에도 기록하지 않는다. …
## 작업
### T-2 — C·D 사건 실행 [담당: GPT ①]   전용: 결과/C_*, 결과/D_*
### T-3 — 심사지침 진단     [담당: GPT ②]   전용: 지침/심사_강도보정_v2.md
## 상태 보고
- T-2 (GPT ①): TODO
- T-3 (GPT ②): TODO
  • 작업마다 담당 + 전용 경로를 못박는다 → 셋이 동시에 써도 충돌하지 않는다.
  • 담당자는 ## 상태 보고의 자기 줄 한 줄만 갱신한다 (DONE / 진행 / 막힘 — 경로·수치).
  • AGENTS.md(Codex 자동 로드)·CLAUDE.md(Claude 자동 로드)에는 "게시판 먼저 읽고 지정 담당만"이라고만 적는다.
  • 관리자는 그 줄을 감시한다:
prev=""; while true; do cur=$(grep -E "^- T-[23]" HANDOFF.md)
  [ "$cur" != "$prev" ] && echo "$cur" && prev="$cur"; sleep 2; done

§3실측 기록 — "손 들어 보세요"

17:00①claude-f0 → claude-13: "막힘 — API 키 없음" (추측으로 넣지 않음)
17:05④HANDOFF를 게시판 형식으로 개편, T-1~T-4 배정
17:07②claude-13 → GPT ①·②: "손 들어! 상태 보고 네 줄을 🙋로 바꿔라" → 입력창에만 남음
17:08②빈 줄 재전송 → 제출. GPT ①: "요청한 한 줄만 확인해 정확히 바꾸겠습니다"
17:09④T-2 (GPT ①): 🙋 손 듦 — claude-13 호출 확인, 지시 대기
17:09④T-3 (GPT ②): 🙋 손 듦 — 감시 스크립트 BOTH_RAISED

관찰: 지시문에 "그 외 파일은 건드리지 말고"를 넣자 Codex는 정확히 한 줄만 고쳤다. 편집 범위를 지시문에 명시하는 것이 곧 안전장치다.

§4재현 절차

  1. 프로젝트 폴더에 HANDOFF.md(게시판), AGENTS.md, CLAUDE.md(둘 다 "HANDOFF 먼저")를 작성한다.
  2. Terminal.app 탭을 여러 개 열고 각각 claude 또는 codex를 같은 폴더에서 실행한다.
  3. 관리자 Claude에서 ps로 Codex tty를, ListAgents로 Claude 동료를 확인한다.
  4. 지시: Claude에는 SendMessage, Codex에는 AppleScript(메시지 + 빈 줄).
  5. 응답: 게시판 상태 보고 줄을 감시한다. 필요하면 history of tab으로 화면을 본다.
  6. 끝나면 교신 타임라인을 협업로그/에 남긴다.

§5한계 · 미검증

  • Terminal.app 전용. iTerm2는 write text, tmux는 send-keys로 대체 가능할 것(미검증).
  • Codex → Claude 직접 push 채널은 없다. Codex가 셸에서 claude -p를 부르거나 파일을 쓰는 방식이 후보(미검증).
  • 타이핑 채널은 Codex가 입력 대기 중일 때만 안전. Working… 중 전송은 큐잉되거나 무시될 수 있음(미검증).
  • 보안: AppleScript 권한을 가진 프로세스는 어느 탭에나 명령을 넣을 수 있다. 신뢰하는 로컬 세션에서만 쓴다.

§6왜 이게 재미있는가

서로 다른 벤더의 에이전트가 공통 프로토콜 없이 협업했다. 필요했던 건 세 가지뿐이다 — 같은 디스크, 같은 터미널 앱, 그리고 "누가 어느 줄을 고치는가"에 대한 합의(게시판). 멀티에이전트 프레임워크가 하는 일의 상당 부분이 사실은 이 합의라는 점이 시사점이다.
