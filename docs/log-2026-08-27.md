## 검증된 채널 3종

### 1. Claude → Claude: 세션 메시지 (즉시·양방향)
- `ListAgents`로 동료 세션 이름 확인 → `SendMessage(to="claude-f0", ...)`.
- 회신은 `<cross-session-message>`로 자동 도착. `notify_when_idle`로 상대가 멈추면 알림.
- 실측: claude-f0가 "API 키 없음 — 막힘"을 스스로 회신 (17:00).

### 2. Claude → Codex: Terminal.app AppleScript 타이핑 (단방향)
- Codex는 Claude 세션 목록에 안 잡힘. 프로세스 목록(`ps -eo pid,tty,command | grep codex`)으로 tty를 찾고, AppleScript로 그 탭에 입력.
  ```applescript
  tell application "Terminal"
    repeat with w in windows
      repeat with t in tabs of w
        if (tty of t) is "/dev/ttys001" then do script "메시지" in t
      end repeat
    end repeat
  end tell
  ```
- **함정**: `do script`의 줄바꿈을 Codex TUI가 제출(Enter)로 안 받음 → 입력창에 텍스트만 남음. `do script "" in t`를 한 번 더 보내야 제출됨. (17:08 실측)
- 탭의 `history of t`를 읽으면 Codex 화면 출력을 엿볼 수 있음 (Codex → Claude 방향의 보조 채널).

### 3. 양방향 공용: `HANDOFF.md` 작업 게시판 (LLM Metrix 방식 계승)
- 관리자가 작업마다 `[담당: …]`·**전용 경로**를 지정 → 담당자는 `## 상태 보고` 자기 줄만 한 줄로 갱신.
- `AGENTS.md`(Codex 자동 로드)·`CLAUDE.md`(Claude 자동 로드)는 게시판 포인터.
- 관리자는 `Monitor`로 상태 보고 줄 변경을 감시 → 파일이 곧 회신 채널.

## 관찰
- Codex 둘은 사용자가 미리 "핸드오프 모드"로 HANDOFF→README→지침을 읽혀둔 상태였음. 그 덕에 한 줄 지시만으로 정확히 한 줄만 고쳤고 다른 파일은 건드리지 않음(요청 준수).
- Codex는 파일 수정 승인 없이 바로 실행됨(사용자 설정 `approvals_reviewer = "user"`지만 이 편집은 프롬프트 없이 통과) — 관리자 쪽에서 편집 범위를 지시문에 명시하는 것이 안전장치 역할.
- 다음 단계: GPT ①에 T-2, GPT ②에 T-3 실행 지시(같은 채널). 키 필요 작업(T-1·T-2)은 사용자가 해당 탭에 export 후 진행.
