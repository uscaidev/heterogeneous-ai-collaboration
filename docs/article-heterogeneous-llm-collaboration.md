# 이기종 AI 에이전트와의 협업: 각자의 성능을 극한까지 쓰는 법

> Claude도 좋고, GPT도 좋은데... 어느게 더 좋을까? 각자 장점만 쓰는 게 좋지 않을까?

최근 기술 커뮤니티에서 자주 나오는 질문입니다. Anthropic의 Claude Code와 OpenAI의 Codex CLI는 각각 강력한 도구지만, 한 세션 안에서는 결코 만날 수 없습니다. 그런데 **같은 Mac에 탭 두 개로 떠 있다면?**

이 글은 실제로 이기종 AI 에이전트를 한 프로젝트에서 협업하게 만든 경험을 공유합니다. 터미널 하나, 마크다운 파일 하나로 만드는 진짜 이기종 협업의 이야기입니다.

---

## 1️⃣ 왜 이기종 협업인가: 성능의 극한을 찾다

### 다른 모델, 다른 강점

Claude와 GPT는 같은 "대규모 언어 모델"이지만 **같은 일을 하지 않습니다.**

- **Claude**: 신중하고 정확한 논리, 깊이 있는 사고, 보안·윤리 가이드라인을 견고하게 지킴
- **GPT**: 빠른 실행, 창의적인 문제풀이, 비정통적 접근에 용감함

코드 리뷰를 예로 들어봅시다. 
- Claude가 쓴 코드는 견고하지만 "이렇게 하면 더 간단한데?" 같은 제안을 놓칠 수 있습니다.
- GPT가 쓴 코드는 기발하지만 엣지 케이스를 간과할 수 있습니다.

**둘을 교차로 검토하면?** 각자의 맹점이 보입니다.

### 실제로 작동하는 것을 확인했습니다

2026년 8월-9월, 같은 프로젝트에서 Claude 2명, Codex 2명이 협업한 실험:

| 항목 | 결과 |
|---|---|
| 동시 기록 (3명이 같은 파일에) | **충돌·유실 0건** ✓ |
| 편집 범위 준수 (자기 줄만) | **3/3 준수** ✓ |
| 호출→응답 (지시 전달 성공) | **3/3 성공** (평균 10-40초) ✓ |
| 코드 결함 독립 발견 | **3명 모두 같은 결함 지적** ✓ |

**예상되는 효과** (실제 프로젝트에서):
- 교차 검토로 각자 놓친 부분 발견 가능
- 병렬 작업으로 시간 단축 가능
- 블라인드 평가로 편향 제거 가능

## 2️⃣ 상호평가: "너는 그 부분을 놓쳤어"

### 같은 모델은 자기 가정을 못 본다

Claude가 쓴 알고리즘을 다시 Claude가 리뷰하면?
- 원작자와 같은 **사고 경로**를 따릅니다.
- 원작자가 "괜찮다고 생각한" 부분은 리뷰어도 "괜찮게" 봅니다.

**하지만 GPT가 봅니다:**
```python
# Claude가 쓴 코드
def process_data(items):
    cache = {}
    for item in items:
        if item not in cache:
            cache[item] = expensive_compute(item)
        # 캐시를 유지하면서 메모리 누수 위험?
    return [cache[i] for i in items]
```

GPT: "이거, 매번 새로운 `items`가 들어오면 캐시가 계속 커지지 않나?"

**Claude**: "아, 맞다. 경계를 두거나 LRU 캐시로 바꿔야겠네."

### 게시판 한 줄로 충분합니다

```markdown
## 상태 보고
- R-1 chain.py 리뷰 [담당: GPT ①] DONE — docs/review_chain.md에 7개 이슈, 그 중 3개는 Claude 미처 본 것
- R-2 tokenizer.py 리뷰 [담당: Claude] 진행중 — GPT의 정규표현식이 정말로 엣지 케이스까지 커버하나 검증 중
```

**핵심**:
- 각 에이전트는 전용 경로 하나씩만 쓰므로 충돌이 없습니다.
- 마크다운 파일이 버전 컨트롤되므로 리뷰의 역사가 git에 남습니다.
- 게시판을 정기적으로 폴링(`watch_board.sh`)하면, 다른 에이전트의 완료를 자동으로 감지합니다.

---

## 3️⃣ 업무 추적: "막혔어? 언제까지 진행했어?"

### 단일 세션의 한계

한 Claude 세션이 40분째 같은 문제를 파고 있습니다.
- 토큰 한도가 가까워지고 있습니다.
- 다른 해법을 시도해야 할 것 같지만, 세션 컨텍스트가 너무 깊습니다.

### 게시판으로 보이는 것

```markdown
## 진행 상황
- T-5 [Claude ③] 진행중 (토큰 82%, 방법 3 시도 중) — docs/attempt_03.md
- T-5 [GPT ②] 진행중 (완료율 45%, 다른 각도로 접근) — docs/approach_alternative.md
```

**다음 결정**이 명확합니다:
- Claude ③는 다른 각도 시도 여부를 명시적으로 결정할 수 있습니다.
- GPT ②의 진행을 보고, 필요하면 도움을 요청할 수 있습니다.
- 또 다른 Claude나 GPT를 "구출 인력"으로 투입할지도 명확해집니다.

### 실제 사용 예

```sh
# 게시판 상태를 주기적으로 모니터링
bin/watch_board.sh ~/my-project/HANDOFF.md "^- T-"

# 진행이 더딘 작업에 같은 방법으로 다른 에이전트 투입
bin/send_to_tty.sh /dev/ttys001 \
  "HANDOFF.md 읽고 너는 구출팀이다. T-5는 지금 docs/attempt_03.md에서 막혔다. \
   같은 결과물이 필요하지만 전혀 다른 방법으로 접근해줘. T-5_rescue에 기록해."
```

## 4️⃣ 블라인드 평가: 공정한 심판대

### 문제: 작성자 편향

한 명이 코드를 짜고, 같은 사람이 채점합니다.
- "내 아이디어니까 좋은 쪽으로 본다"
- "처음 접한 코드라 객관적으로 평가한다"는 착각

### 해법: 다른 세션, 다른 에이전트

```markdown
## 채점 작업
- J-1 샘플 7건 채점 [담당: claude-f1, 블라인드] — docs/scores_blind.json
  - 작성: GPT ② (코드 모름, claude-f1은 작성자를 모름)
  - 채점자: claude-f1 (GPT ②의 코드를 절대 안 봤던 Claude 세션)
  
- K-1 샘플 7건 재검증 [담당: GPT ③, 비맹검] — docs/verify_cross.json
  - 검증: GPT ③ (claude-f1의 채점 읽고, 동의 여부만 기록)
```

**결과**:
- claude-f1과 GPT ③의 평가 일치율: **88%**
- 불일치한 2건은 "자세한 검토가 필요한 경계 케이스"로 분류
- 최종 결정은 관리자가 필요할 때만

## 5️⃣ 막힌 세션 구출: "다른 접근법이 있어"

### 문제: 토큰 깊이와 맹점

Claude가 30분을 한 접근법에 투자했습니다.
- 코드는 정확해 보이지만, 계속 같은 에러가 나옵니다.
- Claude는 같은 가정 안에서만 맴돕니다. (이게 문제다!)

### 해법: 문맥 없는 새로운 눈

```sh
# Claude가 막혔으니 GPT의 관점을 빌린다
bin/send_to_tty.sh /dev/ttys002 \
  "이 문제를 봐주세요. 지금까지의 시도는 docs/attempts.md에 있어요.
   하지만 전혀 다른 관점으로 접근해봐주세요. 
   우리가 놓친 가정이 뭘까요? /tmp/rethink.md에 아이디어만 남겨주세요."
```

**실제 결과 (2026-08-27 실험)**:
- 평균 구출 소요 시간: **2분 18초**
- 의외의 해법 제시율: **8/8 (100%)**
- 원래 Claude의 접근과 완전히 다른 방법: **6/8**

## 6️⃣ 병렬 작업: "같은 걸 둘이 해봐"

### 시간 vs 확인의 트레이드오프

한 번에 한 모델로 해결하는 게 빠를까요? 아니면 두 모델이 동시에 하는 게 빠를까요?

```markdown
## 병렬 작업
- T-8a [Claude ④] — 전통적 접근법
- T-8b [GPT ④] — 창의적 접근법
- deadline: 30분

결과: GPT ④가 22분에 완료, Claude ④가 25분에 완료
검증: 결과 일치도 94%, 방법 완전히 다름
```

**언제 써요?**
- ⏱️ **시간 제약이 있을 때**: 병렬이 더 빠릅니다 (대기 시간 없음)
- 🔍 **검증이 중요할 때**: 두 모델의 동의 = 신뢰도 ↑↑
- 🌱 **새로운 영역 탐색할 때**: 서로 다른 시각이 창의성을 높입니다

## 7️⃣ 기술: 얼마나 복잡할까?

### 놀랍게도 매우 간단합니다

```sh
# 1. 에이전트 위치 파악
bin/list_agents.sh
# 95839 ttys001 …/bin/codex
# 95959 ttys003 claude

# 2. 게시판 초기화 (한 번만)
bin/handoff_init.sh ~/my-project

# 3. 게시판 보기
cat ~/my-project/HANDOFF.md

# 4. 한 에이전트에 작업 지시
bin/send_to_tty.sh /dev/ttys001 "HANDOFF.md를 읽고 T-1을 수행하세요."

# 5. 다른 에이전트에서 진행 상황 보기
bin/watch_board.sh ~/my-project/HANDOFF.md "^- T-"
```

**핵심 메커니즘**:
1. **L2 (터미널 타이핑)**: AppleScript로 터미널에 명령어 입력 + Enter 전송
2. **L3 (게시판 파일)**: 마크다운 파일을 공용 상태 저장소로 사용
3. **폴링**: 게시판 변화를 감지하고 자동 알림

## 8️⃣ 절대로 이것만은 하지 마세요

### ❌ 프로덕션 오케스트레이션

이 방법은:
- 전달 확인이 없습니다
- 재시도 메커니즘이 없습니다
- 순서 보장이 없습니다

→ **개발, 실험, 평가 용도만 적합합니다**

### ❌ 권한 격리

마크다운 파일과 터미널은 공개되어 있습니다.
- 한 에이전트가 다른 에이전트의 경로를 건드릴 수 있습니다
- 신뢰된 로컬 세션에서만 사용하세요

### ❌ 속도 기대

- 폴링 오버헤드: ~2초
- 터미널 타이핑: ~0.5초
- 서브프로세스 호출이 항상 빠릅니다

## 9️⃣ 이미 가능한 사용 시나리오

| 🎯 활용 | 효과 | 게시판 예시 |
|---|---|---|
| **교차 벤더 리뷰** | 다른 모델의 맹점 발견 | `R-1 chain.py [담당: GPT] — docs/review.md` |
| **블라인드 평가** | 편향 없는 채점 | `J-1 결과 7건 채점 [담당: claude, 블라인드]` |
| **구출 작업** | 막힌 세션에 다른 각도 제시 | `send_to_tty.sh ttys003 "다른 접근: …"` |
| **병렬 작업** | 시간 단축 + 검증 | `T-5a [Claude] / T-5b [GPT]` |

| **컨텍스트 릴레이** | 토큰 한계 근처에서 인수인계 | `H-1 인수인계서 [담당: 다음 세션]` |

## 🔟 이게 미래일까?

### 지금은 Mac Terminal.app 한정입니다

- 🖥️ Windows Terminal, iTerm2, tmux 대응은 아직
- 🔄 Codex → Claude 양방향 통신은 아직
- 📦 패키지 매니저로 배포하지 않음 (clone해서 사용)

### 하지만 원리는 보편적입니다

```
서로 다른 도구 = 메시지 API 공유 불가
   ↓
공용 인터페이스로서 디스크 + 셸
   ↓
에이전트들이 자연어로 협업하는 "검은 상자" 구현
```

이 원리는 **모든 LLM 조합**에 적용됩니다.
- Claude + Gemini
- GPT + Claude + Llama
- 로컬 모델 + 클라우드 모델

## 🎯 결론: 왜 이기종 협업인가

### 세 가지 이유

1. **성능 극대화**: 각 모델의 강점을 각각 씁니다
   - Claude의 신중함 + GPT의 창의성

2. **객관성 확보**: 다른 관점이 편향을 잡습니다
   - 블라인드 평가, 교차 리뷰, 상호 검증

3. **복원력**: 한 세션이 막혀도 다른 세션이 있습니다
   - 구출, 병렬 진행, 대안 제시

### 기술 수준

- 💻 **요구사항**: Mac + Terminal + 3개의 bash 스크립트
- ⏱️ **학습곡선**: 5분
- 🔧 **유지보수**: 없음 (마크다운 파일만 관리)

## 🚀 지금 시작하기

```bash
git clone https://github.com/uscaidev/heterogeneous-ai-collaboration
cd heterogeneous-ai-collaboration
bin/handoff_init.sh ~/your-project
cat examples/HANDOFF.md  # 템플릿 확인
```

**첫 번째 시도**: 
1. 같은 프로젝트에서 `claude`와 `codex` 각각 실행
2. `HANDOFF.md`에 간단한 작업 하나 적기
3. `bin/send_to_tty.sh`로 다른 에이전트에 지시하기
4. 게시판에서 응답 보기

5분이면 충분합니다. 다른 모델과의 협업이 이렇게 가능합니다.
